Agents never write to the index

The only way knowledge changes: propose → review → merge → sync.

1

Coding agent

finds a rule that is wrong, stale or missing

2

propose_update

document path, the complete new content, and why

3

briefd

commits on top of the followed branch as briefd/proposal-<id>; never touches the index

4

Pull request

opened on GitHub or GitLab, or linked from the dashboard

5

Human review

merge or close — with a diff and a name on it

Merge → sync → reindex the changed files

The next sync (poll or webhook) picks the merge up; every agent sees the new rule, and the proposal is marked merged.

What agents are told changed because a person decided it — reviewable, revertible, attributable.
